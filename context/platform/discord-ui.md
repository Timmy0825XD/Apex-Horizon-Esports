# UI de Discord (copy, menciones, emojis)

Las personas ven **embeds en inglés**. Emojis de **propósito** (éxito, error, alerta), no adorno. Ver también [ux.md](ux.md).

## Emojis — `emojis.ts`

Un fichero de constantes (`emojis.ts`) guarda los emojis del bot. Cualquier respuesta los **importa** de ahí. No se pegan emojis sueltos en cada comando.

## Componentes reutilizables

Se pueden reutilizar **cascarones** (info / error / success: color, emoji del tipo, layout). Los paneles de `/bot`, `/settings`, `/server`, `/staff config`, el **welcome de `/staff recruit`**, **`/tournament`** (add / edit / delete / info / list / report / role / validate), **`/sheet`** (add / get / find player / validate), **`/team`** (info / list), **`/role`** (user / add all / remove all / list) y **`/user`** (ban / unban) usan **Components V2** (`Container`, `Section`, `Text Display`), no un embed clásico. En add / edit / info de torneo, cada bloque (Identity, Roles, Channels, Ticket categories) va separado con `Separator`; el footer es `-# Created by` con `formatUser` (sin ping). El V2 de `delete` separa **Cleared from the bot** y **Left in place**. Categorías de ticket no configuradas no se listan. En `/sheet find player` y `/sheet get`, cada sheet lista el **nombre del servidor** de origen (texto plano; Discord no menciona guilds). `/sheet get` con `csv` adjunta un **File** V2 (`tournament-sheets.csv`). El aviso de `/sheet find player` en el éxito de `/sheet add` va en un bloque aparte para que el slash no se corte. `/sheet validate` es efímero: un V2 de resumen y un V2 por tipo de fallo. `/team info` pone el **nombre del equipo** como título (emoji `teamName`, sin thumbnail del panel). Torneo y *matched by* van en una línea, con `torneo` y `matchBy`. Un **Separator** delante del primer jugador; cada uno es un **Section** (`### Captain` / `Player N` con la verificación al lado, avatar) con tres líneas: Discord, juego y título. Title lleva `hero` o `legend` si el texto contiene *hero* o *legend*. Footer: `-# Requested by` con `formatUser`. `/tournament role` sin `id_header` manda un V2 naranja de confirmación (qué rol, a todos los jugadores, qué se omite) con botones **Give to all players** / **Cancel**. Tras asignar, responde con un solo V2: los conteos de cada resultado en una línea y, debajo, un bloque por resultado con gente (asignados, no están en el servidor, IDs inválidos, baneados, fallidos), cada uno con su propio título y copy. `/tournament report` es efímero: V2 con el icono del servidor, conteos de asistencia, trabajo y resultados, y un File `.xlsx` (Attendance, Work count, Results, Configuration). `/tournament validate` publica en el canal un V2 de resumen. `/tournament report` es efímero: un V2 con las cuatro hojas del libro, los conteos y un componente File (`.xlsx`). Cada ticket lleva otro V2: título **Group Validation Ticket**, separador, reglas con el rol verificado y el admin del torneo, separador, lista **Issues** (`- @usuario **tag** -` *Not verified* o *Not in server*). Después va un mensaje de texto que menciona a quien quedó en el canal. `/ticket close` ahí avisa en efímero que el canal se borra en **5** segundos, manda el HTML al transcript del topic y borra el canal. `/team list` publica en el canal un V2 por equipo, uno detrás de otro (mismo panel que info, sin *Matched by*). `/role user` es un V2 con el avatar del miembro: verde *Role Granted* o rojo *Role Removed*, cuántos roles tiene y el footer `Granted by` / `Removed by` con hora. `/role add all` y `/role remove all` muestran un V2 naranja de progreso (barra y porcentaje) que se refresca mientras trabajan. Terminan en un solo V2 de resumen con los conteos en una línea (cambiados, ya en el estado deseado, fallidos), sin listar miembros, y footer con autor, duración y hora. `/role list` es efímero: conteos en una línea y las menciones seguidas, separadas en **Humans** y **Bots**, o File CSV si no caben. `/settings` set / edit / show es un solo panel con `### Roles` y `### Channels`; `edit` marca con *updated* lo que cambió y avisa arriba si algo guardado ya no existe. `/server info` reúne identidad, conteos (con boosts) y footer en tres bloques, y el icono es un botón de enlace. Las exportaciones de `/server` llevan el emoji propio de cada una, una línea de conteos, el File y el footer `Exported by`. `/user ban` (rojo) y `/user unban` (verde) usan V2 con mención e ID, thumbnail si hay avatar y footer con autor y hora. Las respuestas de `/utility` siguen el mismo patrón: título `##`, cifras en una línea, footer con autor y hora, botones dentro del container y rojo para lo que borra. Las imágenes llevan el botón **Open full size**. `/staff work` es un Components V2 en el canal: encabezado y tres listas (Judges, Recorders, Judge & Recorder) con mención, matches y games, sin tags. `/staff config`, `/tournament` add / edit / info siguen el patrón de `/settings`: bloques `###`, etiquetas cortas, *updated* en lo que cambió, aviso con `alert` si algo ya no existe y footer con autor y hora. `/staff recruit` / `fire`, `/ticket` close / reopen / delete y `/tournament delete` dicen en una frase qué cambió y llevan footer con mención y hora; lo que borra o quita va en rojo. `/schedule` publica todo en **Components V2**: el post, los results, **New Schedule** y el resto de respuestas. Los pings van en un Text Display encima de la tarjeta (en V2 notifican; dentro de un embed no). `/schedule show` lista (5 por página) o abre la ficha del partido, también en V2: verde si hay resultado, dorado si está pendiente, rojo si la hora pasó sin resultado. `/schedule unassigned` es otro V2 dorado, 5 por página: cada partido muestra hora, estado, torneo, canal y las líneas de juez y recorder; *Open* marca el puesto vacío. Con el filtro de cualquier puesto, agrupa ambos vacíos, solo juez y solo recorder. No incluye schedules que ya tienen resultado o cuyo ticket está cerrado. Asignar juez o recorder, renunciar o reemplazar y confirmar asistencia son un V2 de una línea en el ticket (verde al entrar, naranja al salir). Ningún mensaje de ese flujo es efímero. `/bracket upload` y `/bracket correct` responden con **Components V2**. `/utility embed create` publica un **embed clásico**; `/utility v2 create` publica **Components V2**. Un adjunto en V2 (p. ej. `/server banlist`) lleva un componente **File** que apunta a `attachment://nombre`; si solo se sube el archivo sin ese componente, Discord lo descarta.

`/panel tutorial` abre un V2 efímero con un menú de familia, otro de comandos y la cola numerada; al enviar, se borra y publica una guía V2 por comando con el mismo molde (eyebrow, título con mención, resumen, *Who can use it*, *How it works*, *Options*, *Keep in mind*, *Related*, footer `Staff guide N of M`) y el color y emoji de su familia. Detalle en [../commands/panel.md](../commands/panel.md).

**No** reutilizar el mismo texto en varios bloques de la misma respuesta. Si hay tres embeds de éxito, cada uno describe **su** hecho, no un “Success” genérico repetido.

## Entidades: menciones, no nombres

En descripciones de embed y texto visible al usuario **no** se usa `role.name`, `user.tag`, `user.username` ni `channel.name`. Se usan helpers para que un recurso borrado tenga el mismo fallback.

| Entidad | Helper | Output |
|---|---|---|
| Role (by ID) | `formatRole(guild, roleId)` | `<@&roleId>` |
| Role (object) | `formatRoleFromRole(role)` | `<@&roleId>` |
| Text/announcement channel | `formatChannel(guild, channelId)` | `<#channelId>` |
| Category | `formatCategory(guild, categoryId)` | `<#categoryId>` |
| User (by ID) | `formatUser(userId)` | `<@userId>` |
| User (object) | `formatUserFromUser(user)` | `<@userId>` |
| Guild member | `formatMember(member)` | `<@userId>` |

Preferir helpers frente a `` `<@&${id}>` `` inline.

**Excepciones:** CSV/Excel y nombres de archivo de audit pueden llevar identificadores en texto plano (no son UI de Discord). El ID *es* el dato en banlist/sheet.

Menciones de slash commands: siempre clicables, `</name sub:id>`. Al registrar los comandos, el bot guarda el ID de **todos** por servidor; `slashMention(guildId, "name sub")` arma la mención. Lo usan `/bot help` y cualquier mensaje que nombre un comando (errores incluidos). Solo si el ID aún no existe (antes del registro) cae a `` `/comando` `` en código. Un comando con subcomandos no se puede mencionar sin el subcomando.

El battle ticket (el canal del partido) abre con un Components V2: título `lado VS lado` (emoji `vs`; tag del capitán en `1vs1`, nombre del equipo si el formato es de más de un jugador), debajo **Tournament:**, **Round:** y **Group:** solo si hay grupo, cada equipo con la línea del capitán al mismo nivel que los in-game ID y el avatar del capitán, reglas y deadline. El footer es el **Match ID** y la fecha y hora exactas en que terminan las **36 horas** (`día/mes/año` y hora), en la zona horaria de quien ve el mensaje. La descripción del canal es `Tournament ID: <id de Challonge> | Match ID: <id del match>`. Ese V2 queda fijado en el canal. El mensaje de texto que va después hace ping a los capitanes. `/ticket` responde con V2 efímero. En un ticket de `/tournament validate`, `/ticket close` avisa en efímero que el canal se borra en **5** segundos, publica el HTML en el canal de transcript del topic y borra el canal. `/attendance mark` publica el mismo Components V2 en el ticket y en el canal de asistencia, sin thumbnail: título `##`, la fase en `-#` (grupo y ronda), el marcador en `###`, torneo y ticket en una línea, separador, y **Judge** y **Recorder** con la mención al lado (una sola línea **Judge & Recorder** si es la misma persona). Los links de grabación son botones de enlace *Recording N* (5 por fila) y solo aparecen si hay URLs. El footer es `Uploaded by` con mención y la fecha y hora. `/attendance delete` repite ese layout en rojo con el registro borrado, el motivo en cita y el footer `Deleted by`. `/attendance report` menciona a la persona (no usa su username), lista cada rol con partidos y games, el **Total** en `##` con las tarifas en `-#`, y los botones GOLD / AC al final. `/schedule` publica el schedule creado como Components V2 (ticket y canal de schedules); encima van las menciones de los capitanes y el ping sale en el ticket. Al actualizar, ese texto incluye también al juez y al grabador si están asignados, y el ticket vuelve a publicar el mensaje para hacer ping. `/schedule results add` publica otro Components V2 (ticket y canal de resultados); el texto del ticket dice **Match Complete**, menciona a los capitanes y les hace ping. Las demás respuestas del comando son **Components V2** en el canal. El éxito y los errores de `/schedule update` son efímeros. Asignar juez o recorder, renunciar o reemplazar y confirmar asistencia son un V2 de una línea en el ticket. El recordatorio T-10 y el aviso urgente T-2 también son V2. El molde de las tarjetas de `/schedule` vive en [../commands/schedule.md](../commands/schedule.md). `/bracket upload` responde con **un solo** Components V2 que se edita en cada paso, con el logo de Challonge como thumbnail. Lleva `## Score Uploaded` con la fase en `-#`, el marcador en `###` con el emoji `winner`, y torneo y ticket en una línea. Si hay `note`, va en cita. Después vienen los pasos: marcador guardado, ticket archivado (emoji `open_close`) y transcript publicado (emoji `transcript`). Un paso pendiente sale en `-#` y uno fallido con el emoji `error`. El footer es `Uploaded by` con mención y hora, y al final va el botón de enlace **View transcript**. El acento es naranja mientras trabaja o si un paso falla, y verde al terminar. `/bracket dq both` usa la misma tarjeta en rojo, con el emoji `banned` de thumbnail, las líneas **Advances** / **Eliminated** y los forfeits automáticos con marcador y fase. La advertencia de `/bracket correct` es un Components V2 con el logo de Challonge, la fase, el marcador anterior → nuevo, el ganador nuevo, un ticket por línea (canal · fase · estado) y tres viñetas de consecuencias. **Confirm correction** (rojo) y **Cancel** van dentro del container. El éxito, con o sin tickets aguas abajo, es otro Components V2 con el emoji de Challonge como thumbnail: fase, marcador nuevo con `winner`, antes → ahora, tickets rehechos y footer `Corrected by` con mención y hora. La cancelación lleva `Cancelled by`. `/room auto` apagado, ya encendido, o el error antes de leer el bracket, también. `/room create` y el encendido de `/room auto` se publican en el canal: un V2 con el filtro en `-#` y **Created** · **Errors** · **Waiting** en una línea. Debajo van el cupo de las categorías y, si aplica, **Issues**: `- @capitán · **equipo**` si no está en el servidor; tag, equipo e ID si el Discord ID es inválido. El footer dice quién lo abrió, cuándo, y menciona `/room available`. Verde si todo salió bien, naranja con errores, rojo si no abrió ninguno. No lista los canales creados. `/room available` se publica en el canal: V2 de barra verde, *Available Rooms* con el torneo y el conteo, y cada partido en una línea (número, emoji `vs`, lados y fase, con el grupo solo si hay grupos). Los `_` de los tags se escapan para que no activen la cursiva. Pasa de 20 y aparecen flechas con el indicador `1/N`. Los avisos de `/room auto` muestran la próxima ejecución como hora relativa. `/link missing` es un Components V2 naranja: el torneo con el conteo de pendientes y, si se pasó `user`, esa persona. Un separador y después cada partido en dos líneas. La primera tiene el emoji `vs`, los lados y la fase. La segunda tiene el recorder con mención (sin tag), cuándo se marcó y el ticket. 10 por página, con flechas y el indicador `1/N`. Los partidos `DW` no aparecen: el link no es obligatorio. `/link add` y `/link delete` responden con un V2 que repite el encabezado de partido de `/attendance mark` (fase, marcador, torneo y ticket). `add` es verde y trae botones de enlace para los links nuevos. `delete` es rojo, o azul de aviso si no había links y no toca nada. Los dos llevan footer con mención y hora. `/get attendance` es un V2 azul con el avatar de la persona, 5 registros por página y flechas. `/get sheet` es un V2 efímero con el resumen del libro y el `.xlsx` en un componente **File**.

## Énfasis (markdown de Discord)

| Estilo | Sintaxis | Uso |
|---|---|---|
| Bold | `**text**` | Nombres de equipo/torneo, labels, conteos |
| Italic | `*text*` | Notas secundarias, stage, copy de ayuda |
| Underline | `__text__` | Divisores de sección. Nunca `__vs__` |
| Matchup | `name vs name` | Los dos lados de un partido, en texto plano. Escapa `_` y `*` del nombre (`escapeDiscord`) |
| Monospace | `` `text` `` | Scores, Match IDs, slugs de canal, números crudos |
